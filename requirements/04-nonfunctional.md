## 4. 비기능 요구사항

가장 중요한 기준은 **경로 한 건을 2초 안에** 돌려주는 것과 **인증키를 밖에 내보이지 않는 것**이다.

| ID | 분류 | 요구사항 | 기준 |
| --- | --- | --- | --- |
| NFR-01 | 성능 | 경로 계산 응답 | 출발·도착 직선 3km 이내에서 최단+상황 경로 2개를 2초 안에 |
| NFR-02 | 성능 | 외부 API 응답 저장 | 기상청 초단기실황은 매시 한 번만 바뀌므로 격자마다 1시간 저장. 에어코리아는 서버가 1시간마다 '전국'을 한 번에 받아 저장(하루 24번, 한도 500번). 새 API는 필요 없음 (4.3) |
| NFR-03 | 안정성 | 외부 API가 죽어도 경로는 나옴 | 날씨·대기 정보 없이도 밤 여부만으로 계산하고 "날씨 정보 없음"을 표시 |
| NFR-04 | 정확성 | 데이터 없는 지역을 안전하다고 말하지 않음 | 시설 데이터가 빈 지역은 "데이터 부족"으로 표시하고 점수는 중립값 |
| NFR-05 | 보안 | 인증키 관리 | 키는 `.env`에만 두고 git에 올리지 않음. 앱에는 키를 넣지 않고 서버가 대신 호출 |
| NFR-06 | 보안 | 키 노출 점검 | 프로젝트 파일 중 키가 들어 있는 것은 .env뿐임을 확인. 채팅 기록이나 화면을 남과 공유할 때만 재발급 |
| NFR-07 | 개인정보 | 위치 기록 안 함 | 사용자의 출발·도착 좌표를 서버 DB나 로그에 남기지 않음. 자주 가는 곳·길 기록(FR-39·39-1)은 휴대폰 안에만 두고 서버·LLM에 보내지 않음 |
| NFR-08 | 라이선스 | 출처 표시 | 지도 아래에 데이터 출처를 표시. 생활안전지도(공공누리 4유형)는 상업적 이용·변경 금지 |
| NFR-09 | 확장성 | 전국 확장 | 시설은 전국을 한 DB에 두고, 길찾기는 출발·도착 주변만 읽어 메모리를 일정하게 유지 |
| NFR-10 | 이식성 | DB 서버 교체 | `.env`의 DB 주소만 바꾸면 학교 MySQL로 옮길 수 있음 |
| NFR-11 | 사용성 | 휴대폰 화면 | 폭 375px에서 가로 스크롤 없이 사용 |
| NFR-12 | 유지보수 | 재현 가능한 데이터 갱신 | 내려받기·적재를 몇 번 다시 해도 같은 결과 |
| NFR-13 | 개인정보 | 광고·분석 도구 없음 | 앱에 광고·분석 SDK를 넣지 않고, 위치는 보호자 알림(FR-27) 말고는 휴대폰 밖으로 보내지 않음. 안전 앱의 위치 판매·광고 사용 논란(Life360 등)을 피하려고 |
| NFR-14 | 사용성 | 걷기 불편한 사람도 쓰기 쉬운 화면 | 1차. 휴대폰 글자 크기 설정을 따르고 버튼은 크게, 한 화면에는 한 가지 일만. 경로는 색만이 아니라 선 모양으로도 구분. 휠체어 사용자가 한 손으로 쓸 수 있게 주요 버튼은 화면 아래쪽에. 중요한 안내는 글과 음성 둘 다(음성은 2차). 노인·휠체어 사용자 2명 이상에게 직접 써 보게 하고 고침 |

### 4.1 전국에서 쓰기 위한 조건

설계는 전국용이지만 2026-10-29 기준으로 아직 전국에서 쓸 수 없다. 아래 세 가지가 채워져야 한다.

1. **도로망 적재.** OSM 파일은 받았지만 DB에 없어 경로 계산이 아직 어디서도 안 된다(A파트, 광주 먼저).
2. **학교 밖에서 접속되는 서버·DB.** 학교 MySQL은 학교 네트워크 안에서만 접속된다(0.5의 '서버를 어디에').
3. **지역별 데이터 편차 표시.** 시설 데이터는 전국에 있지만 고르지 않다. 예: 비상벨 서울 28,560개 · 부산 563개, 보안등 제주는 재난안전데이터에 0개였지만 전국보안등정보표준데이터를 더해 23,376개, 가로등은 받는 중이라 아직 전 지역 0개. 빈 곳은 안전하다고 하지 않고 "데이터 부족"으로 표시한다(NFR-04, 6.3).

### 4.2 외부 서비스가 멈출 때

경로 계산은 우리 DB만으로 돌아서 외부 API가 멈춰도 대부분 계속 된다. 가장 큰 약점은 **우리 서버와 DB가 하나뿐**이라는 점이다.

| 멈추는 것 | 영향 | 경로 | 대응 |
| --- | --- | --- | --- |
| 공공데이터 API (재난안전데이터·생활안전지도·공공데이터포털) | 데이터 갱신만 못 함 | 나옴 | 이미 DB에 저장돼 있음. 재난안전데이터 키는 2027-10-28 만료라 그 전에 재발급 |
| 기상청·에어코리아 | 비·폭염·미세먼지 판단 불가 | 나옴 | 마지막 값을 쓰고, 없으면 "정보 없음". 밤은 API 없이 일몰 계산 (NFR-03) |
| 카카오 장소 검색 | 이름으로 검색 불가 | 나옴 | 지도를 눌러 고르기, 현재 위치, 자주 가는 곳(FR-39)·최근 간 곳 목록(휴대폰에 저장) |
| 카카오맵 SDK (지도 화면) | 지도가 안 보임 | 계산은 됨 | 지도 없이 문장 안내("200m 직진 후 편의점 앞에서 오른쪽")와 시설 목록을 보여 줌. 예비 지도(OSM 타일)를 둘지는 0.5에서 결정 |
| TMAP | 비교 평가만 못 함 | 영향 없음 | — |
| LLM (설명 다듬기, 3차) | 다듬은 문장이 안 나옴 | 나옴 | 기본 문장(FR-06)을 그대로 보여 줌. 3초 넘게 답이 없거나 검사를 통과하지 못해도 같음(3.5) |
| **우리 서버·학교 DB** | **경로 계산 불가** | **안 나옴** | 앱은 "서버에 연결할 수 없음"을 분명히 알리고, SOS·경보음·보호자 문자는 서버 없이 동작. 시연은 노트북 로컬 MySQL로 대비(11장) |
| 인터넷 (걷는 도중) | 새 경로를 못 받음 | 받아 둔 경로 유지 | 귀가 지킴이는 GPS와 문자(휴대폰망)로 계속 동작. 경로 주변 시설 목록은 출발할 때 받아 둠 |
| ODsay (대중교통) | 걷기+대중교통 경로 불가 | 도보 경로는 나옴 | "대중교통 경로를 불러올 수 없음"을 표시하고 도보 경로만 보여 줌. 한도를 아끼려고 같은 출발·도착 결과는 잠시 저장 |

어떤 경우든 앱은 무엇이 안 되는지 화면에 알리고("날씨 정보 없음", "서버에 연결할 수 없음"), 작동하는 척하지 않는다.

### 4.3 실시간 구현 문제

'실시간'이 걸린 곳은 네 군데다. 1번은 해결했고, 2번은 해결 방안을 정했고, 3·4번은 안드로이드 앱에서 **해결해야 하는 문제**다.

| # | 문제 | 상태 | 해결 방안 / 검토할 방법 | 파트 |
| --- | --- | --- | --- | --- |
| 1 | **날씨·대기 API 한도 초과.** 에어코리아를 시도마다 30분에 한 번 부르면 하루 약 770\~820번으로 개발계정 한도(500번)를 넘음. 기상청도 사용자가 여러 지역에 흩어지면 하루 1만 번을 넘을 수 있음 | 해결 (NFR-02 수정) | 새 API 없이 부르는 방식만 바꿈. 에어코리아는 1시간마다 '전국'을 한 번에 받아 저장(하루 24번). 기상청 실황은 매시 갱신이므로 격자마다 1시간 저장. 시연 뒤에도 운영하면 운영계정 신청 | C |
| 2 | **경로를 2초 안에 못 낼 수 있음.** 요청마다 주변 길(3km면 수만 구간)을 학교 DB에서 네트워크로 읽어 그래프를 만드는 구조라 느릴 수 있음 (NFR-01) | 해결 방안 정함, 측정 필요 | 시연 지역 도로망과 길별 감점을 서버가 켜질 때 메모리에 올려 두고, 요청 때는 DB를 읽지 않음. 다른 지역은 지금처럼 범위만 읽되 공간 인덱스로 한 번에 가져옴. 도로망을 넣은 뒤 조선대 주변 30쌍으로 응답 시간을 재고, 2초를 넘으면 탐색 범위(사방 500m)를 줄임 | A, B |
| 3 | **걷는 동안 위치 따라가기.** ① 화면이 꺼지면 안드로이드가 백그라운드 위치를 막음 ② 도심에서 GPS가 5\~20m 이상 튀어 가만히 있어도 '경로 이탈'로 오판할 수 있음 ③ 신호 대기와 진짜 멈춤을 구분하기 어려움 ④ 계속 켜 두면 배터리를 많이 씀 | **해결해야 하는 문제** | ① 포그라운드 서비스(상단에 "귀가 지킴이 실행 중" 알림 고정) ② 정확도가 30m보다 나쁜 값은 버리고 몇 번의 위치를 평균, '30초 이상 계속 벗어남' 조건 유지. 벗어나면 SOS 대신 먼저 다시 안내(FR-35)하므로 GPS가 잠깐 튀어도 SOS가 뜨지 않음 ③ 시험 걷기로 멈춤 기준(3분) 조정 ④ 도착하면 바로 끄고 위치 주기를 1\~3초 안에서 조절, 배터리가 낮으면 절전 모드(FR-40)로 화면 밝기·위치 주기를 줄임. 화면과 GPS가 배터리를 가장 많이 쓰므로 효과는 실제 휴대폰으로 재야 함. 어느 방법이 맞는지는 실제 휴대폰으로 시험해야 함 | D |
| 4 | **SOS 화면·경보음·문자.** ① 최근 안드로이드는 백그라운드 앱이 잠금 화면 위에 화면을 띄우지 못하게 막음 ② 무음·방해금지 모드에서 경보음이 안 울릴 수 있음 ③ 문자 자동 발송 권한(SEND\_SMS)은 플레이스토어 정책 제한이 있음 | **해결해야 하는 문제** | ① 전체 화면 알림 권한(안드로이드 14부터 사용자가 직접 허용)을 처음 설정 때 받기 ② 알람 채널로 울리고, 방해금지 예외 허용을 설정 때 안내 ③ 시연은 직접 설치라 괜찮음. 스토어 배포를 한다면 문자 앱을 열어 주는 방식이나 서버 문자 발송을 검토. 안드로이드 버전별로 실제 휴대폰에서 시험해야 함 | D |

**'실시간'이 아닌 것.** 가로등·CCTV 같은 시설 데이터는 분기마다 갱신하는 정적 데이터라 꺼진 가로등·고장 난 CCTV는 모른다. 보호자에게 위치를 계속 보여 주는 기능도 없고 알림 때 문자로 한 번 보낸다. 발표에서는 "실시간 날씨·시간 + 정기 갱신 시설 데이터"라고 말한다.
