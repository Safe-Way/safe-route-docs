### 5.2 받기와 적재

1. `scripts/download_national.py`가 API를 1,000건씩 받아 `data/raw/national/<이름>/p00001.json`으로 저장한다. 받은 쪽은 건너뛰고, 하루 한도(키마다 990번)에 걸리면 다음 날 0시 10분에 이어서 받는다.
2. Java `FacilityImporter`(실행 프로필 `import`)가 파일을 읽어 좌표를 WGS84로 바꾸고 종류별 표(`security_light`, `cctv` 등)에 5,000건씩 넣는다. 같은 출처는 지우고 다시 넣어서 몇 번을 실행해도 결과가 같다.
3. 출처별 전체·적재·제외 건수와 다 받았는지는 `data_source` 표에 남긴다.
4. 갱신은 분기마다 1번, 또는 시연 전에 1번 한다.

### 5.3 데이터를 보며 발견한 점

아래의 조선대 수치는 시연 지역을 국립아시아문화전당 주변으로 옮기기 전(2026-10-30)에 조사한 것이다(결정 37). 두 곳은 약 1.3km 떨어진 같은 동구 서남동이고 새 범위(반경 2km)가 조선대를 포함해 경향은 같다. 새 범위 도로망에는 횡단보도 점 348개(신호 있음 87, 없음 110, 모름 151)와 계단 구간 27개가 있고, 보도턱 표시는 1개뿐이다. 범위 안 육교 5곳은 모두 휠체어로 못 지나간다.

- **전국 CCTV·보안등 데이터는 출처마다 빈 곳이 다르다.** 조선대 1km 안에 CCTV는 전국 파일 25곳·광주시 파일 92곳이다. 보안등은 재난안전데이터에 4개뿐이지만 동구청 파일과 전국보안등정보표준데이터에는 각각 784개가 있다. 시연 지역은 지자체 파일과 표준데이터로 보충한다.
- **광주·전남 통합으로 주소가 바뀌었다.** 새 데이터는 "전남광주통합특별시"로, 예전 데이터는 "광주광역시"로 적혀 있다. 그래서 지역은 주소 글자가 아니라 좌표로 고른다.
- **재난안전데이터는 지역으로 거르는 기능이 없다.** 전국을 다 받은 뒤 DB에서 좌표로 고른다.
- **한파쉼터는 출처를 바꿨다.** 생활안전지도는 트래픽 제한으로 10,000건까지만 줘서 전국 일부만 들어 있었다. 재난안전데이터(`DSSP-IF-10804`)로 바꿔 전국 54,378건을 넣었다(2026-10-29).
- **보안등은 출처 세 곳이 겹친다.** 동구청 파일과 전국보안등정보표준데이터는 같은 등을 담고 있어 조선대 1km 안 건수가 784개로 같다. 길 점수를 계산할 때 10m 안에 겹치는 같은 종류 시설은 하나로 보아 두 번 세지 않는다. 표준데이터를 더해 제주 보안등이 0개에서 23,376개가 됐다.
- **시설이 없다는 것과 데이터가 없다는 것은 다르다.** 시·군·구별로 시설 밀도를 계산해 크게 낮은 지역은 "데이터 부족"으로 표시한다(NFR-04).
- **OSM에는 휠체어용 정보가 거의 없다.** 조선대 주변(약 2km × 2km) 걸을 수 있는 길 1,144개 중 휠체어 표시는 3개, 경사는 16개, 보도 폭은 0개였다. 횡단보도 143곳에는 보도턱 정보가 하나도 없고 엘리베이터 표시도 없다(2026-10-30 Overpass로 확인). 계단(15곳)과 바닥 재질(367개 길)만 쓸 만하다. 그래서 휠체어 모드(FR-46)는 횡단보도·육교 표준데이터로 채우고(경사는 결정 36에서 뺌), 정보가 없는 곳은 "확인 안 됨"으로 둔다.

## 6. 경로 비용 모델

길 하나의 비용은 **길이에 상황별 감점을 곱한 값**이다. 감점이 모두 0이면 최단 경로와 같고, 감점이 클수록 같은 길이도 더 멀게 친다. 조선대 데이터로 돌려 본 결과와 바꿀 점은 6.5에 있다.

```latex
\text{cost}(e) = \text{length}(e) \times \left(1 + \sum_{k} w_k(\text{상황}) \cdot p_k(e)\right), \quad 0 \le p_k(e) \le 1
```

### 6.1 감점 항목

감점은 모두 0\~1로 맞춘다. 시설 수는 길이로 나눠서, 긴 길이 시설이 많아 보이는 것을 막는다.

| 감점 | 계산 | 쓰는 데이터 | 결합 반경 |
| --- | --- | --- | --- |
| 밝기 부족 | 1 − min(1, 조명 수 ÷ (길이 ÷ 25m)) | 가로등 + 보안등 | 30m |
| CCTV 부족 | 1 − min(1, 카메라 대수 ÷ (길이 ÷ 50m)) | CCTV (10m 안 중복은 하나로) | 50m |
| 도움 지점 멀음 | min(1, 가장 가까운 도움 지점까지 거리 ÷ 300m) | 경찰·편의점·지킴이집·비상벨 | 길 가운데에서 300m |
| 덮개 없음 | 덮인 길이면 0, 아니면 1 | OSM `covered`, `tunnel`, `indoor` | — |
| 계단 | 계단이면 1, 아니면 0 | OSM `highway=steps` | — |
| 무더위쉼터 멀음 | min(1, 가장 가까운 쉼터 ÷ 500m) | 무더위쉼터 | 500m |
| 한파쉼터 멀음 | min(1, 가장 가까운 쉼터 ÷ 500m) | 한파쉼터 | 500m |
| 큰 차도 | 간선·주간선도로 1, 보조간선 0.5, 나머지 0 | OSM `highway` 등급 | — |

### 6.2 상황별 가중치 (초깃값)

상황이 겹치면 가중치를 더한다. 값은 설정 파일에 두고 2주차 평가로 조정한다.

| 감점 | 평소 | 밤 | 비 | 폭염 | 한파 | 미세먼지 |
| --- | --- | --- | --- | --- | --- | --- |
| 밝기 부족 | 0 | 1.0 | 0 | 0 | 0 | 0 |
| CCTV 부족 | 0 | 0.6 | 0 | 0 | 0 | 0 |
| 도움 지점 멀음 | 0 | 0.4 | 0 | 0 | 0 | 0 |
| 덮개 없음 | 0 | 0 | 0.5 | 0.2 | 0 | 0 |
| 계단 | 0 | 0.1 | 0.3 | 0 | 0.3 | 0 |
| 무더위쉼터 멀음 | 0 | 0 | 0 | 0.4 | 0 | 0 |
| 한파쉼터 멀음 | 0 | 0 | 0 | 0 | 0.4 | 0 |
| 큰 차도 | 0 | 0 | 0 | 0 | 0 | 0.5 |

### 6.3 규칙

- **최대 우회:** 상황 경로가 최단의 1.3배를 넘으면 가중치를 절반으로 줄여 다시 찾는다. 3번 후에도 넘으면 최단 경로를 주고 그 사실을 알린다.
- **데이터 없음:** 시·군·구의 시설 밀도가 전국 중간값의 10% 아래인 종류는 그 지역에서 감점을 0.5(중립)로 두고 화면에 "데이터 부족"을 표시한다.
- **미리 계산:** 감점 p는 상황과 관계없으므로 길마다 미리 계산해 DB에 저장하고, 요청 때는 가중치만 곱한다.
- **차이 설명:** 두 경로가 지나는 시설 수(결합 반경 안)를 종류별로 세어 차이가 큰 순서로 3개까지 문장에 넣는다. 시간은 보행 속도 분당 80m로 환산한다.

**휠체어 모드 (FR-46, 3차, 초깃값).** 다른 모드와 달리 "지나갈 수 없는 길"은 감점이 아니라 그래프에서 뺀다: 계단, 엘리베이터 없는 육교·지하보도. 감점은 보도턱 안 낮춘 횡단보도 +1.0, 고르지 않은 바닥 +0.3, 정보 없는 횡단보도 +0.2(그리고 "확인 안 됨" 표시)로 둔다. 밤 감점은 청년·중년과 같게(×1) 하고, 최대 우회는 1.5배, 속도는 분당 60m다. 값은 사용자 확인과 평가로 고친다. 경사는 휠체어 모드에도 쓰지 않으므로(결정 36) 화면에 "경사는 확인하지 않은 길"이라고 알린다.

### 6.5 경로 엔진 시험 결과와 정할 것 (B파트, 2026-10-30)

B파트(원일)가 6.1\~6.4 값을 조선대 주변 실제 데이터(OSM 길 5,100개와 팀 DB 시설)로 돌려 본 결과다. 무작위 출발·도착 200쌍(직선 0.5\~3km)을 모드별로 비교했다. 원문은 B파트의 「경로 엔진 결정 사항」과 코드 저장소의 `docs/route-weights.md`다.

**결론.** 지금 식(감점을 길이에 곱함)으로는 어린이·노인 모드가 거의 작동하지 않는다. 계단(평균 34m)이나 횡단 구간(절반이 30m 미만)처럼 짧은 길에 붙은 감점은 비용이 몇 m밖에 안 붙기 때문이다. 밤에 노인이 계단을 피한 경우는 0%였다. 휠체어의 제외 규칙은 확실히 작동했다(계단 0곳). 계단·횡단을 지날 때마다 고정 비용을 더하는 방식으로 바꾸자 세 지역 모두에서 작동했다.

| 확인한 것 (조선대 200쌍) | 지금 식 | 추천 규칙 |
| --- | --- | --- |
| 낮 노인이 계단을 피함 | 3/18쌍 | 14/18쌍 |
| 밤 노인이 계단을 피함 | 0/14쌍 | 4/14쌍 |
| 낮 어린이가 신호 없는 횡단을 줄임 | 44/102쌍 | 87/102쌍 |
| 밤 어린이가 신호 없는 횡단을 줄임 | 34/112쌍 | 80/104쌍 |
| 낮 어린이 우회율 | 1.028 | 1.055 |
| 휠체어 경로의 계단 | 0곳 | 0곳 |

광주 북구·서울 관악구에서도 같은 방향이었다. 낮 노인 계단 회피는 25\~44%에서 70\~78%로, 어린이의 신호 없는 횡단 감소는 31\~43%에서 85\~100%로 올랐다. 대가는 우회다. 대부분 2\~4% 더 돌고, 횡단이 OSM에 많이 그려진 북구에서 어린이는 12.5% 더 돌았다(한도 30% 안).

**고정 비용을 넣은 식 (제안).** n은 그 길에서 계단·횡단을 지나는 횟수, c는 모드별 고정 비용(m)이다.

```latex
\text{cost}(e) = \text{length}(e) \times \left(1 + \sum_k w_k\, p_k(e)\right) + \sum_j n_j(e)\, c_j
```

| 고정 비용 | 제안값 | 근거 (세 지역 민감도 분석) |
| --- | --- | --- |
| 노인 계단 | 300m (낮·밤 같음) | 효과가 멈추는 점이 150\~300m. 값을 키워도 우회가 거의 늘지 않아 넉넉하게 둠 |
| 어린이 신호 없는 횡단 | 200m, 밤에는 어린이 밤 배수 ×1.5를 곱해 300m | 낮 100\~200m, 밤 200\~300m에서 효과가 멈춤. 밤에는 밝기 가중치와 경쟁해 더 커야 함 |
| 어린이 신호 모르는 횡단 | 80\~120m (신호 없음보다 작게) | 효과가 멈추는 점이 없음. 너무 크면 실제로 신호가 있는 횡단까지 피해 우회만 늘어남. 서울 관악구는 횡단의 90%가 "모름"이라 이 값이 결과를 좌우함 |
| 어린이 신호 있는 횡단 | 40m | 바꾸지 않음 |

지역마다 값을 따로 두지 않고 전국 값 하나와 우회 한도로 지역 차이를 막는다. 어린이의 큰 차도 가중치(+0.5)만 있고 횡단 비용이 없으면, 큰길을 피해 골목으로 돌면서 신호 없는 횡단을 어른보다 오히려 더 많이 건넌다(북구 낮 −52%). 그래서 두 값은 함께 써야 한다.

**조선대 육교 적용 결과.** 도내기시장앞육교(필문대로)는 현장에서 철거를 확인했다. 남초교육교(남문로)는 한쪽에만 보행 노드가 있어 실패 목록에 들어갔고 위성지도 확인이 필요하다. 그래서 만든 육교 길은 0개다. OSM 보행용 다리 9개 중 차도를 건너는 것은 1개뿐이라, 나머지 8개(하천·캠퍼스 다리)는 육교 감점을 0으로 바꿨다.

**A파트가 먼저 할 일 (2026-11-02 확인).**

- **가로등 적재**: 끝남(2026-11-02). 전국 2,253,201건을 빠짐없이 넣었다. 광주 범위는 가로등 67,116개와 보안등 52,596개, 조선대 1km 안은 가로등 286개와 보안등 1,572개다. B파트가 이전에 돌린 밝기 감점은 가로등이 빠진 상태였으니 다시 돌려야 한다.
- **행정구역(시·군·구) 경계 받기**: 끝남(2026-11-02). SGIS 2025년 2분기 경계로 광주 시도 1·구 5·행정동 96을 admin\_area 표에 넣었다. 코드는 SGIS 번호(광주 24)라 행정표준코드(29)와 다르므로, 시설·길이 어느 구에 있는지는 좌표로 찾는다. 경계로 다시 세면 횡단보도 표준데이터는 동구 3·북구 282건이다.
- **도로망 범위**: 시연 지역(아시아문화전당 반경 2km)부터 넣었다(2026-11-02, 점 6,431·구간 8,569). 다른 지역은 같은 스크립트(scripts/load\_road\_network.py)로 범위를 주고 더 넣는다. 칸 설계는 B파트 road\_network.sql이 올라오면 맞춘다.
- **길별 원값(`edge_stat`) 계산**: 끝남(2026-11-02, 아래 결과). 코드(migration 007\~009, `scripts/load_road_network.py`·`load_boundaries.py`·`build_edge_stat.py`)는 safe-route의 `feature/security-light-std` 브랜치에 커밋했고 아직 원격에는 올리지 않았다.
- **광주 범위 시설 수 (참고)**: CCTV 9,718, 무더위쉼터 1,835, 한파쉼터 1,705, 편의점 1,449, 공중화장실 911, 비상벨 301, 지킴이집 246, 횡단보도 표준데이터 285, 경찰 61.
- **원일 님께 요청**: `road_network.sql`과 `route.yml`을 원격 저장소에 올려 주면 칸 이름을 맞춘다.

**edge\_stat 계산 (2026-11-02, 김재휘 안대로).** 아시아문화전당 반경 2km의 길 8,569개에 위 원값을 모두 채웠다(`scripts/build_edge_stat.py`, 약 20초). 보안등·CCTV는 같은 종류 10m 안 중복을 하나로 셈다. 우선 결과:

- 등 30m 안에 드는 길이 64%, CCTV 50m 안 38%. 행정동별로 충장동 91%·계림1동 90%는 밝고, 서남동 45%·양림동 29%는 낮다(서남동은 조선대 캠퍼스에 등 자료가 없음).
- 가장 가까운 도움 지점까지 평균 123m(최대 839m), 지킴이집 364m, 쉼 곳 128m.
- 횡단: 길에 붙은 횡단 209번(신호 있음 27, 없음 54, 모름 128). 나머지 횡단 점은 보행 길 없이 차도 위에만 있어 붙이지 않았다(C4). 보도턱을 아는 횡단은 1곳뿐이다.
- 차도 옆 인도 411개 중 187개가 15m 안 차도 등급을 물려받았다(C5).
- 육교 위 보행 길 2개는 모두 휠체어로 못 지나감.
- 아직 안 한 것: 데이터 부족 비트(`data_gap`)는 전국 시군구 경계를 넣은 뒤 구 단위로 판정한다. B파트가 없는 칸이나 다른 기준을 원하면 스크립트만 고쳐 다시 돌린다.
