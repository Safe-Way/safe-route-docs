## A. 경로 엔진 시험 결과와 결정 과정 (B파트, 2026-10-30\~11-03)

아래는 6.1\~6.4 기준을 정하기까지의 기록이다. B파트(원일)가 처음 안(길이에 상황별 감점을 곱하는 식과 상황·모드별 가중치 초깃값, 2026-10-29)을 조선대 주변 실제 데이터(OSM 길 5,100개와 팀 DB 시설)로 돌려 본 결과에서 시작한다. 무작위 출발·도착 200쌍(직선 0.5\~3km)을 모드별로 비교했다. 아래 값 중에는 지금 쓰지 않는 것도 있으니, 지금 기준은 6.1\~6.4와 `route.yml`을 본다. 원문은 B파트의 「경로 엔진 결정 사항」과 코드 저장소의 `docs/route-weights.md`다.

**결론.** 처음 식(감점을 길이에 곱함)으로는 어린이·노인 모드가 거의 작동하지 않는다. 계단(평균 34m)이나 횡단 구간(절반이 30m 미만)처럼 짧은 길에 붙은 감점은 비용이 몇 m밖에 안 붙기 때문이다. 밤에 노인이 계단을 피한 경우는 0%였다. 휠체어의 제외 규칙은 확실히 작동했다(계단 0곳). 계단·횡단을 지날 때마다 고정 비용을 더하는 방식으로 바꾸자 세 지역 모두에서 작동했다.

광주 북구·서울 관악구에서도 같은 방향이었다. 낮 노인 계단 회피는 25\~44%에서 70\~78%로, 어린이의 신호 없는 횡단 감소는 31\~43%에서 85\~100%로 올랐다. 대가는 우회다. 대부분 2\~4% 더 돌고, 횡단이 OSM에 많이 그려진 북구에서 어린이는 12.5% 더 돌았다(한도 30% 안).

**고정 비용을 넣은 식 (제안).** n은 그 길에서 계단·횡단을 지나는 횟수, c는 모드별 고정 비용(m)이다.

```latex
\text{cost}(e) = \text{length}(e) \times \left(1 + \sum_k w_k\, p_k(e)\right) + \sum_j n_j(e)\, c_j
```

| 고정 비용 | 제안값 | 근거 (세 지역 민감도 분석) |
| --- | --- | --- |
| 노인 계단 | 300m (낮·밤 같음) | 효과가 멈추는 점이 150\~300m. 값을 키워도 우회가 거의 늘지 않아 넉넉하게 둠 |
| 어린이 신호 없는 횡단 | 200m, 밤에는 어린이 밤 배수 ×1.5를 곱해 300m | 낮 100\~200m, 밤 200\~300m에서 효과가 멈춤. 밤에는 밝기 가중치와 경쟁해 더 커야 함 |
| 어린이 신호 모르는 횡단 | 80\~120m (신호 없음보다 작게) | 효과가 멈추는 점이 없음. 너무 크면 실제로 신호가 있는 횡단까지 피해 우회만 늘어남. 서울 관악구는 횡단의 90%가 "모름"이라 이 값이 결과를 좌우함 |
| 어린이 신호 있는 횡단 | 40m | 바꾸지 않음 |

지역마다 값을 따로 두지 않고 전국 값 하나와 우회 한도로 지역 차이를 막는다. 어린이의 큰 차도 가중치(+0.5)만 있고 횡단 비용이 없으면, 큰길을 피해 골목으로 돌면서 신호 없는 횡단을 어른보다 오히려 더 많이 건넌다(북구 낮 −52%). 그래서 두 값은 함께 써야 한다.

| 한파쉼터 멀 `cold` | 0 | 0 | 0.4 |
| 계단 (지날 때마다 고정 비용) | +50m | 0 | +50m |

노인은 `heat`·`cold`에 ×1.5, 비·한파 때 계단에 +100m를 더 두는 안이다. 문화전당 주변은 무더위쉼터까지 평균 143m라 고정 500m 기준으로는 길을 구별하지 못하고, 덮인 길은 OSM에 0.2%(3.7km)뿐이라 비 오는 날 경로를 실제로 바꾸는 것은 계단 고정 비용이다. 상가 아케이드(충장로 등)의 덮개 정보는 따로 보충해야 한다.

**그 밖에 보류한 것.** 외진 길(골목) 감점, 미세먼지(안내 문구로만), 노인 녹색신호 시간(조선대 주변 녹색시간 자료 0건).

## B. 카카오맵 키 넣는 방법과 앱 설정 (D파트)

카카오맵 SDK 연결은 앱 저장소 safe-route-android에 들어 있다(PR #9). 지도에는 서버의 `KAKAO_REST_KEY`가 아니라 같은 카카오 앱의 **네이티브 앱 키**를 쓴다. 서버 `.env`에는 넣지 않고 앱의 `local.properties`(git에서 빠짐)에 둔다.

1. 카카오 개발자 사이트 → 내 애플리케이션 → `KAKAO_REST_KEY`를 받은 앱 → 앱 키에서 **네이티브 앱 키**를 받는다. Admin 키는 앱에 넣지 않는다.
2. 같은 앱의 플랫폼 → Android에 패키지 이름 `com.deungbul.anshimgil`과 **자기 키 해시**를 등록한다. 키 해시는 컴퓨터마다 다르므로 팀원마다 한 번씩 추가한다(아래 명령).
3. 제품 설정의 카카오맵 사용 설정이 꺼져 있으면 켠다.
4. 앱 프로젝트 맨 위 폴더의 `local.properties` 맨 아래에 아래 두 줄을 넣고 Sync한 뒤 실행한다.

```bash
keytool -exportcert -alias androiddebugkey -keystore ~/.android/debug.keystore -storepass android -keypass android | openssl sha1 -binary | openssl base64
```

```properties
# 카카오맵 SDK용 네이티브 앱 키 (git에 올리지 않음)
KAKAO_NATIVE_APP_KEY=여기에_네이티브_앱_키
# 서버 주소. 에뮬레이터에서 이 컴퓨터의 서버는 http://10.0.2.2:8080, 비워 두면 예시 데이터
SERVER_BASE_URL=
```

`app/build.gradle.kts`가 이 두 값을 읽어 BuildConfig로 넘기고, `SeipjidoApp.kt`가 키가 있을 때만 SDK를 초기화한다. 지도 대신 "키와 키 해시 등록을 확인해 주세요"가 나오면 2번(키 해시)부터 확인한다. 에뮬레이터(API 37)에서 지도가 뜨는 것은 확인했다(PR #9, 2026-10-30).
